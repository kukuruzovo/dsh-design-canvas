# Design Canvas — архитектура

Внутренний справочник: слои, модель, контракты, рецепты расширения. Пользовательское описание
(что умеет плагин, операции, экспорт, установка) — [README.md](../README.md); правила и инварианты —
[AGENTS.md](../AGENTS.md); известные дефекты — [BACKLOG.md](BACKLOG.md).

## 1. Слои и зависимости

```
schema.js ──► store.js ──┐
    │        ops.js ─────┼──► service.js ──► tools.js ──┐
    │        export.js ──┘        │                     ├──► index.js
    └─────────────────────────────┴──► route.js ────────┘
                                     client.js (браузер, отдельный контракт)
```

| Файл | Ответственность | Импортирует |
|---|---|---|
| `schema.js` | модель документа: константы, нормализация, обход, токены, компоненты, layout, валидация, контраст | ничего |
| `store.js` | файлы: реестр проектов, `.design/`, ревизии, корзина, атомарная запись | `node:fs`, `node:os`, `node:path`, `schema.js` |
| `ops.js` | 16 операций над документом, транзакционный конвейер | `schema.js` |
| `export.js` | HTML/CSS, режимы `fidelity`/`clean`, страница библиотеки компонентов | `schema.js` |
| `service.js` | сценарии: стык schema+store+ops+export; результат — JSON для агента и панели | все четыре |
| `tools.js` | 9 инструментов агента | `ops.js` (список операций), `service.js` |
| `route.js` | HTTP `/api/dsh-design-canvas` | `service.js` |
| `index.js` | точка входа Cordis: инструменты + маршрут | `tools.js`, `route.js` |
| `client.js` | панель-редактор | React через `require`, HTTP через `/api/dsh-design-canvas` |

Циклов нет; `schema.js` не знает ни про файловую систему, ни про HTTP, ни про React.
Единственный модульный мутабельный счётчик — `idCounter` в `schema.js`.

**Правило границ.** Логика живёт в `schema/store/ops/export/service`. `tools.js` и `route.js`
разбирают аргументы и рендерят результат; `client.js` рисует и собирает правки. Правило поведения,
продублированное в адаптере, — дефект: исключение сделано только для разворачивания инстансов
в панели (она правит документ до сохранения, поэтому не может ждать серверный `display`).

## 2. Модель документа

### Верхний уровень файла `<canvas-id>.canvas.json`

`format: "dsh-design-canvas"`, `version: 1`, `id`, `name`, `device`, `createdAt`, `updatedAt`,
`tokens`, `components`, `root`, `rev`.

- `format`/`version` фиксируются нормализацией; чужой `format` → 400.
- `rev` — **поле файла, не модели**: добавляется при записи и возвращается отдельно, `normalizeDoc`
  его отбрасывает.
- `device` — из `DEVICE_PRESETS`, иначе `mobile`: `mobile 390×844`, `tablet 834×1112`,
  `desktop 1440×900`, `component 240×56`.
- `root` — фрейм с жёстко заданными `id: 'root'`, `type: 'frame'`, `locked: true`; внутри один
  фрейм `page` размером с пресет устройства и заливкой `token:color.bg`.

### Узел

Базовые поля: `id`, `type`, `name`, `x`, `y`, `w`, `h`, `rotation`, `visible`, `locked`, `style`, `layout`.
Условные: `text` (только `text`), `image` (только `image`), `component` + `overrides` (только
`instance`), `clip` + `children` (контейнеры), `autoW`/`autoH` (только у фрейма и только когда
значение задано явно — иначе старый `canvas.json` обрастал бы новыми полями). Транзиентные, только
в развёрнутом дереве: `instanceOf`, `missing`, `expanded`.

- Типы: `frame`, `group`, `rect`, `ellipse`, `line`, `text`, `image`, `instance`; контейнеры —
  `frame`, `group`, `instance`.
- `style`: `fill`, `stroke` (`{width, color}`), `radius`, `opacity`, `shadow`. Обрезка детей — поле
  узла `clip`: `true` у фрейма из шаблона устройства и у фрейма, добавленного операцией `add` без
  явного значения.
- `text`: `value`, `token` (голый путь типографики), `align`, `valign`, `color`, а также
  `size`/`weight`/`lineHeight`/`letterSpacing` как точечные переопределения токена.
- `layout`: `mode` (`none`/`vertical`/`horizontal`), `gap`, `padding {t,r,b,l}`, `align`
  (`start`/`center`/`end`/`stretch`), `justify` (`start`/`center`/`end`/`space-between`).
  `justify` распределяет свободное место по главной оси, `align: 'stretch'` растягивает детей по
  поперечной; свободное место есть только у фрейма с авторским размером по этой оси, поэтому при
  `justify !== 'start'` авторский размер сохраняется вместо подгонки по содержимому. Арифметика
  продублирована в панели (`layoutFrame` в `client.js`) — расхождение меняет файл при сохранении,
  паритет значений проверяет `smoke-client.mjs`.
- Координаты абсолютные **относительно родителя**; размеры — собственные.
- Ограничения: `MAX_DEPTH = 64` (глубже дети обрезаются), `MAX_NODES = 20000` (проверяется
  валидацией), холст больше 8 МБ не читается и не записывается (`MAX_CANVAS_BYTES`, 413).

Нормализация идемпотентна: валидный id сохраняется, иначе генерируется; числа приводятся `num()`;
`w`/`h` не меньше нуля; `visible` — всё кроме `false`; `locked` — только `true`.

## 3. Токены

Группы по умолчанию: `color` (bg, surface, surfaceAlt, border, fg, fgMuted, accent, accentFg,
danger, success), `radius` (sm/md/lg/pill), `space` (xs…xl), `font` (sans, mono), `text`
(h1/h2/body/caption — составные), `shadow` (card/pop — составные).

- Ссылка — строка `token:<путь>`; исключение — `text.token`: **голый путь** без префикса, потому что
  токен составной.
- `flattenTokens` даёт и составные узлы (`text.h1`), и листья (`text.h1.size`).
- Единицы при экспорте: `radius.*`, `space.*`, `text.*.size`, `text.*.letterSpacing`,
  `shadow.*.{x,y,blur,spread}` → `px`; `text.*.weight`, `text.*.lineHeight` — безразмерные.
- В CSS ссылка становится `var(--<путь через дефис>, <литерал>)`; отсутствующий токен → warning и
  `transparent`; составной токен в роли заливки не выводится.
- Валидация (`validateDoc`): отсутствующий токен → `warn missing-token`; авторские дети инстанса →
  `warn instance-children` (содержимое берётся из компонента, эти узлы не отрисуются); контраст
  текста к фону предков ниже порога → `warn low-contrast`. Порог — 4.5:1 для мелкого текста и 3:1
  для крупного (24px и больше либо полужирный от 18.66px); цвета читаются из hex, `rgb()`/`rgba()`
  и ссылок на токены, полупрозрачный текст смешивается с фоном, `opacity: 0` пропускается. Текст
  без заданного цвета не проверяется: панель и экспорт отдают его темой.
- `normalizeTokens` оставляет plain-object группы, примитивы и один уровень вложенности; пустой
  результат заменяется дефолтами.

## 4. Компоненты

Компонент: `{ key, name, description, node, props }`; `node` — шаблон узла с координатами 0/0.

Параметр: `{ type, default, description, target, property }`, где `type` — `text`/`color`/`number`/
`boolean`/`token`. `property` по умолчанию: text → `text.value`, color/token → `style.fill`,
number → `w`, boolean → `visible`.

`target` разрешается так:

| `target` | Куда попадает значение |
|---|---|
| `root` (по умолчанию) | корень шаблона |
| `text` | первый текстовый узел в порядке обхода |
| `#Имя` | первый узел с таким именем |
| иной путь | путь от корня с индексами: `children[0].label` |

`overrides` инстанса: ключ, совпавший с объявленным параметром, идёт через `target` + `property`
(ненайденный `target` пропускается молча); незнакомый ключ трактуется как путь от корня шаблона
(`style.fill`, `text.value`, `w`).

**Разворачивание.** Инстанс не несёт содержимого: шаблон копируется при чтении, отрисовке и
экспорте, а `children` инстанса при этом игнорируется. Нормализация их не вычищает — чужой файл не
должен молча терять данные, — поэтому непустой массив остаётся в `canvas.json` и попадает в
`validateDoc` как `warn instance-children`. К копии применяются `overrides`, затем **всем** узлам поддерева присваивается id
`<instanceId>/<templateId>`, а корню возвращается id инстанса. Такой id не проходит `ID_RE`, то есть
заведомо транзиентен и на диск не попадает. Ненайденный компонент даёт узел с `missing: true` и
пустыми детьми. Вложенные инстансы разворачиваются с лимитом глубины 32.

`detach` превращает инстанс в обычный узел (с сохранением id); `delete-component` по умолчанию
сначала детачит все инстансы.

## 5. Операции

Конвейер `applyOps(doc, ops, opts)`: принимает массив или одну операцию (пустой массив — ошибка,
больше 2000 операций — ошибка), работает на **полной копии** нормализованного документа, применяет
операции по порядку (каждая видит результат предыдущих), затем пересчитывает потоковую раскладку
(`relayout`, если не отключено) и обновляет `updatedAt`. Возвращает `{ doc, results }`; ошибка любой
операции → `OpsError` с `opIndex` и отказом от всего батча.

| Операция | Поля |
|---|---|
| `add` | `parent`, `node` или `type`, `index`, `after` |
| `update` | `id`/`ids`, `patch` (слияние по ключам: `style`, `text`, `layout`, `image`, `overrides`, `padding`) |
| `move` | `id`, `parent`, `index`, `after` (запрет циклов) |
| `delete` | `id`/`ids` (`root` нельзя) |
| `duplicate` | `id`/`ids`, `count` (1…100), `offsetX`, `offsetY`, `parent` |
| `group` / `ungroup` | `ids`, `name` / `id` |
| `reorder` | `id`, `index` или `direction` (`front`/`back`/`up`/`down`) |
| `set-tokens` | `tokens`, `remove` (пути токенов), `replace` |
| `define-component` | `key`, `from`, `name`, `description`, `props`, `convert` |
| `delete-component` | `key`, `detach` |
| `instantiate` | `component`, `parent`, `x`, `y`, `w`, `h`, `overrides`, `index`, `after` |
| `detach` | `id` |
| `set-canvas` | `name`, `device` (проверяется по `DEVICE_PRESETS`) |
| `align` | `ids`, `mode` (`left`/`center`/`right`/`top`/`middle`/`bottom`), `axis` |
| `distribute` | `ids`, `axis` (`x`/`y`) |

`relayout` собирает фреймы с `layout.mode !== 'none'`, сортирует по глубине по убыванию и раскладывает
снизу вверх: позиции детей выводятся из порядка, `gap`, `padding`, `align`, размер подгоняется по
содержимому (если `autoW`/`autoH` не `false`). `outline` даёт плоский список узлов без корня.

## 6. Хранилище

- Раскладка: `<корень проекта>/.design/` — `<canvas-id>.canvas.json`, `project.json` (создаётся
  `ensureProject`, а также `writeCanvas` при первой записи холста), `exports/`.
- Реестр: `$DSH_DESIGN_CONFIG` или `$DSH_HOME/design-canvas.json`; читается лениво, чтобы тесты
  подменяли `DSH_HOME`. Файл мержится поверх встроенного списка проектов; `null` удаляет проект,
  строка трактуется как `{root}`, `~` разворачивается.
- Корзина: `$DSH_HOME/design-trash/<stamp>_<project>_<canvas>/` + `meta.json`; восстановление —
  обратный `rename`, при существующем холсте нужен `overwrite`.
- Разрешение проекта: id реестра → путь внутри известного корня (самый длинный корень) → подъём
  вверх до 40 уровней в поисках `.design/` → `ensureProject` при `create` → иначе ошибка.
- Запись — только атомарная: временный файл рядом + `rename`.
- Ревизия: `rev` отсутствует → 1; запись → `currentRev + 1`; `expectRev` сравнивается строго,
  несовпадение → 409 с `{rev, expected}`, обходится только `force`.
- Защита путей: id холста и токенов по `ID_RE`, метка корзины — длина 1…200 и только
  `[A-Za-z0-9_.-]` без `.`, `..`, `/`, `\`; имена экспорта проходят `basename`.

## 7. Сервис

Все view-функции возвращают обычный JSON-объект — он же результат инструмента агента и тело
HTTP-ответа. Это единственное место, где соединяются модель, файлы, операции и экспорт.

`projectsView`, `canvasesView`, `readView` (режимы `summary`/`outline`/`node`/`tokens`/`components`/`full`),
`displayView` (развёрнутое дерево для панели), `createView`, `applyBatch`, `exportView`, `validateView`,
`tokensView`, `componentsView`, `trashView`, `initProjectView`, `writeDocView`.

Ошибки: `ServiceError` и реэкспортированный `StoreError` несут `status` и `payload`; `OpsError`
превращается в `ServiceError` 400 с payload `{opIndex, op}`.

## 8. Экспорт

`renderDocument(doc, {mode, frame, title, inlineCss, components})` → `{html, css, files, warnings}`.

- Файлы: `<id>.html`, `<id>.css` и `<id>.components.html`, если есть компоненты.
- Верхние фреймы — экраны: в обоих режимах они встают потоком доски `.dc-board`, поэтому
  координаты внутри `root` на страницу не переносятся и экраны из одной точки не накладываются.
- `fidelity` — абсолютное позиционирование внутри фреймов; `clean` дополнительно делает
  flex-контейнерами фреймы с `layout.mode !== 'none'`. Потоковый узел с absolute-детьми получает
  `position:relative` и остаётся их containing block.
- Каждый элемент несёт `data-node` и `data-name`; скрытые узлы выходят HTML-комментарием.
- Токены — `:root { --<путь через дефис>: значение }` (составные токены пропускаются), типографика и
  тень выводятся с литеральными fallback внутри `var(...)`.
- Страница библиотеки компонентов рендерит каждый компонент один раз через синтетический инстанс.
- Предупреждения: ненайденный фрейм, изображение без `src`, отсутствующий токен.

## 9. Инструменты агента

`registerTools(ctx, config)` регистрирует девять инструментов; `config.project` подставляется, когда
агент не назвал проект. Общие элементы: `parameters.additionalProperties: false`, `output.schema`,
`output.render` → текстовые блоки, `presentCall` → карточка.

| Инструмент | Назначение |
|---|---|
| `design_projects` | реестр проектов и холстов, `init` |
| `design_create` | создать холст (устройство, шаблон, сразу батч) |
| `design_read` | проекции документа |
| `design_apply` | основной инструмент: батч операций |
| `design_tokens` | чтение и правка токенов |
| `design_components` | библиотека: `list`/`get`/`define`/`instantiate`/`detach`/`delete` |
| `design_export` | HTML + CSS + библиотека в `.design/exports/` |
| `design_validate` | дубли id, битые инстансы, токены, обрезка, контраст |
| `design_delete` | корзина: `list`/`delete`/`restore` |

Описания операций собираются из `OPS` + `OP_HELP` в `OP_SCHEMA` и переиспользуются в `design_apply`
и `design_create`, поэтому новая операция документируется в одном месте. Требования к описаниям —
скил `agent-experience`.

## 10. HTTP-маршрут

`/api/dsh-design-canvas`, предел тела 16 МБ, ответ всегда JSON, `cache-control: no-store`.

```
GET  /projects /canvases /canvas /display /outline /tokens /components /validate /export /trash /config
POST /create /init /apply /canvas /tokens /components /export /delete /restore
```

Статус ответа берётся из `status` ошибки сервиса. Различия адаптеров: `design_read` по умолчанию
`summary`, `GET /canvas` — `full`; `GET /export` принудительно отдаёт превью без записи файлов.

## 11. Коды ошибок

| Код | Когда |
|---|---|
| 400 | недопустимый id холста или метки корзины, каталог не проект, чужой `format`, неизвестное действие, ошибка операции (`{opIndex, op}`) |
| 404 | нет холста, проекта, каталога, записи корзины |
| 409 | холст уже существует; ревизия устарела (`{rev, expected}`) |
| 413 | холст больше 8 МБ; тело запроса больше 16 МБ |
| 500 | повреждённый JSON холста; в записи корзины нет файла |

## 12. Решения и их причины

| Решение | Причина |
|---|---|
| Холсты в репозитории проекта, а не в `$DSH_HOME` | дизайн версионируется вместе с кодом, едет в git и лежит рядом с приложением |
| Документ — обычный JSON с абсолютными координатами | простой diff, чтение без миграций, предсказуемая отрисовка |
| Инстанс — ссылка без детей | правка компонента обновляет все инстансы; копия разошлась бы с шаблоном |
| Батч операций транзакционен, откат — работа над копией | нет журнала и полусобранных состояний; ошибка в середине не портит документ |
| `rev` + `expectRev` | человек и агент правят один файл; без ревизии правки затираются молча |
| Один сервис на инструменты и панель | правила не расходятся между половинами |
| Разворачивание инстансов на сервере (`GET /display`) | правило живёт в одном месте; панель дублирует его только для локальных правок |
| Клиент без JSX и без ESM | бандл отдаётся как есть, без сборки; React приходит из загрузчика модулей |
| Токены-ссылки вместо литералов | смена токена перекрашивает макет и экспорт |
| Корзина вместо удаления | холст — данные пользователя, удаление восстановимо |

## 13. Рецепты расширения

**Новая операция.** Обработчик в `ops.js` + запись в `OPS`; описание в `OP_HELP` (`tools.js`) — оно
само попадёт в схему инструментов; при необходимости действие в панели; строка в таблице README;
проверка в `smoke.mjs` (включая откат при ошибке в середине батча).

**Новое поле узла.** Нормализация в `schema.js` (значение по умолчанию + сохранение старого файла);
слияние в `mergeNodePatch`; отрисовка в `client.js`; вывод в `export.js`; проверка в `validateDoc`.
Все четыре потребителя обязательны.

**Новый инструмент.** View-функция в `service.js`; регистрация в `tools.js` (схема, `output.render`,
`presentCall`); маршрут в `route.js`, если нужен панели; точный список имён в `smoke-tools.mjs`;
строка в README.

**Новый маршрут.** Функция сервиса → запись в таблицу маршрутов `route.js` → вызов из `client.js`
через `api(...)` → маршрут в известном наборе `smoke-client.mjs`.

**Новая возможность экспорта.** `export.js` (только `schema.js` на входе, никакого ввода-вывода) →
предупреждения в общий список → проверка в `smoke.mjs` → описание в README.
